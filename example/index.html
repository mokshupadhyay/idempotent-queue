Two tabs, one queue

Each frame below runs its own queue, like a separate tab. They share IndexedDB, Web Locks and BroadcastChannel, because they have the same origin. One of them holds the sender lock and sends. Enqueue a payment in either frame, then close the sending frame while its request is in flight: the other frame takes over and sends the same key again. The pretend server applies it once. Opening tab.html in two real tabs works the same way.
